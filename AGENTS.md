# DSH config maintenance

- Deployment commands preview by default; only an explicitly authorized apply may change a target installation. Do not modify real DSH profiles, installations, sessions, or storages, or restart a Host without explicit authorization.
- Public files must not contain actual machine endpoints, authentication headers, credentials, Cloudflare Access metadata, usernames, or private filesystem paths. Keep them in ignored `private/`; generated output is private too.
- Files named `DONT_READ_THIS_IF_YOU_ARE_AGENT*.md` are runtime text, not agent instructions. Unless the user explicitly requests content inspection, do not open, search, preview, quote, or print them into agent context, including through Read, Grep, or diffs. Rename, copy, or compare them programmatically without emitting contents; exclude them from broad content searches.
- Exclude `generated/` and `private/` from broad content searches. Inspect only filenames and sizes for structure; inspect specific private content only when explicitly needed and authorized, without printing secrets.
- Tests own their temporary files and register automatic cleanup for success and failure; test logs must not overwrite maintenance logs.
- `private/` holds machine parameters, dependency input snapshots, and private records with an ongoing maintenance purpose. Keep machine inputs and dependency snapshots still consumed by source planning; do not accumulate disposable Release metadata, empty logs, test scratch, or downloaded tool installers there. Tests clean their own temporary directories; maintenance logs and update backups belong under `generated/` with the retention rules in README.md.
- Use Nunjucks with `[[ ... ]]` variables and `[% ... %]` blocks, HTML escaping disabled and undefined interpolation rejected. Preserve DSH `{{cwd}}`, `{{model}}`, and literal `!!js`; never evaluate expressions or read credential files while rendering.
- Managed package references must use verified, exact GitHub Release asset URLs; the local prompt module is synced as repository code, without a package dependency. Never invent an asset or substitute a different version automatically; report unresolved sources.
- Run focused tests, example renders, and current machine checks when private inputs exist. Inspect staged content before publishing; do not encode real machine identifiers in public checking rules.
- A DSH patch targets a row by `id` and **replaces that row's entire `config` value**, never deep-merging keys; any row this repository renders must restate every key it still needs. Insert new rows with `- insert:`, and swap a provider by disabling the original row by `id` and inserting the replacement — two providers cannot register the same service key.
- Do not add a generic YAML deep merge engine. Whole private plugin rows currently preserve machine-specific provider/MCP configuration; extract smaller parameters only with focused rendering tests.
